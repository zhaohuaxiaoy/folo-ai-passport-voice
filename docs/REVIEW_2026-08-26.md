## 3. 新问题(审计之后 / 修复引入)

### P2-A 悬浮窗被 `session_end` 过早关掉,随后 partial 再打开

- **位置**:`relay.py:560-561` 在设备 `voice.end` 时立刻 `on_phase("session_end")`;`fre_app.py:542-544` 对 `session_end` 调用 `_floating_hide()`;`fre_app.py:557-564` 对后续 partial 再 `_floating_show()`。
- **触发**:松手 → 设备立刻发 `voice.end` → ASR 还在出 partial/final(通常再 200ms–2s)。
- **影响**:窗先消失再闪回来;若 ASR 超时没有 final,窗会一直留在屏幕上。PRD 把 `session_end` 当「无 final 的兜底隐藏」,但时序上它几乎总是先于 final。
- **现有测试**:`test_candidate_poll_wiring` 只灌 candidate,不交叉 `session_end`。
- **置信度**:85。
- **修法**:`session_end` 不要立刻 hide;只在 `is_final` / `disconnected` / `relay_done` / `error` 隐藏,或对 `session_end` 做短延迟且期间忽略新 partial。

### P2-B 向导填了 API Key,状态页仍显示「未配置」

- **位置**:`fre_app.py:377-381` `on_asr_next` 只 `write_asr_cfg(key)` 写盘,不更新 `self.cfg`;`fre_app.py:532-536` 状态页读 `self.cfg.get("volcano_api_key")`。
- **触发**:首次运行、内存 cfg 无 key、用户在向导里粘贴 key。
- **影响**:ASR 实际能用(`StreamingASR` 从磁盘 `load_config()`),但状态页显示「未配置」。首次体验的核心反馈是错的。
- **置信度**:95。
- **修法**:`self.cfg = {**self.cfg, "volcano_api_key": key}`,或使用 `write_asr_cfg` 的返回值。

### P2-C `audio_streamer_start()` 拒绝时状态机不知情

- **位置**:`audio_streamer.c:197-202` 残留未排空则 return,不置 `s_active`;`main.c:103-107` `APP_ACT_STREAM_START` 不检查返回值;`app_state.c:459-462` 已把 `stream_started=true`。
- **触发**:上一会话 BLE notify 拥塞,drain 200ms 超时,用户再次 PTT。
- **影响**:屏幕在 LISTENING、计时在走,但没有 PCM。用户以为在录音。这是审计 P1-3「start 排空」修复引入的缺口:正确性优先于泄漏,但失败没有回传归约器。
- **置信度**:75(需 BLE 拥塞,不是每次)。
- **修法**:`start()` 返回 `esp_err_t`;失败则回 READY + toast,或投 `AUDIO_ERROR`。

### P2-D Windows 悬浮窗 `lift()` 可能抢焦点

- **位置**:`floating.py:84-87` 首次 show 调 `deiconify()` + `lift()`。文档写了不调 `focus_force`,但 Windows 上 `overrideredirect` + `lift` 仍常把前台从输入框抢走,导致 final 注入打到错误窗口。
- **置信度**:60(依赖合成器,**NOT RUN**)。
- **修法**:Windows 用 `GWL_EXSTYLE` / `WS_EX_NOACTIVATE`,或去掉 `lift()`,真机验证。

## 5. 架构与文档漂移

`ai-passport/AGENTS.md` 仍写:

> pure-BLE direct connection … **No Wi-Fi/WS/mDNS/HID in this architecture.**

实际产品是 BLE / WiFi / USB 三通道,companion 向导、mDNS、USB SYS 命令面都在 `main`。按这份 AGENTS.md 工作的 agent 会把 WiFi/USB 当错误实现删掉。

README 已经是三通道合同,AGENTS.md 落后。这是 agent 安全问题,不是文案问题。

另外:`main.c` 作为唯一执行器的边界大体还在;`app_ui.c` 仍 include `bsp_battery.h`(电量已由主循环写入快照),是小的层泄漏。
